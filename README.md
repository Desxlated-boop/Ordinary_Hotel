# Ordinary Hotel Booking System

Полнофункциональное веб-приложение для бронирования отелей, разработанное на стеке: React + SCSS (клиент) и Node.js + Express + PostgreSQL (сервер).

## 🌟 Функционал сайта

### Для гостей и пользователей:
1. **Регистрация и Вход**: Быстрое создание профиля и авторизация на основе JWT-токенов.
2. **Просмотр номеров**: Главная страница с популярными предложениями и страница «Номера» со всем перечнем комнат.
3. **Бронирование**: Возможность забронировать любой номер на выбранный диапазон дат под определенным именем гостя.
4. **Кабинет пользователя**: Просмотр собственной истории бронирований с актуальными статусами (подтверждено / отменено).

### Для администраторов (Панель управления):
1. **Управление номерами**: Добавление, редактирование (изменение названия, описания, цены, вместимости, фото) и удаление номеров.
2. **Загрузка изображений**: Возможность быстрой загрузки файлов картинок для номеров непосредственно через интерфейс.
3. **Контроль бронирований**: Общий список всех заказов в системе с возможностью отменить любое бронирование.
4. **Управление пользователями & Безопасность**:
   - Блокировка и разблокировка пользователей прямо из списка бронирований.
   - **[НОВОЕ]** Автоматическая отмена всех подтвержденных бронирований пользователя при его блокировке.
   - **[НОВОЕ]** Администратор защищён от случайной блокировки самого себя.

## 🚀 Инструкция по запуску проекта

Для запуска проекта на локальном компьютере вам потребуются установленные **Node.js** и **PostgreSQL**.

### Структура папок:
* `client/` — фронтенд приложение на React (Vite).
* `server/` — бэкенд на Node.js (Express REST API).
* Папка корня проекта содержит скрипты для одновременного запуска обеих частей.

---

### Шаг 1: Настройка базы данных PostgreSQL

1. Создайте базу данных в PostgreSQL:
   ```bash
   createdb hotel_db
   ```
2. Разверните структуру таблиц и базовые данные из файла схемы:
   ```bash
   psql -d hotel_db -f server/src/db/schema.sql
   ```

---

### Шаг 2: Запуск бэкенда (Server)

1. Перейдите в каталог `server`:
   ```bash
   cd server
   ```
2. Установите зависимости:
   ```bash
   npm install
   ```
3. Создайте файл окружения на основе примера:
   ```bash
   cp .env.example .env
   ```
4. Откройте `.env` и настройте параметры подключения:
   - `DATABASE_URL` = URL доступа к вашей БД PostgreSQL (например, `postgresql://postgres:пароль@localhost:5432/hotel_db`).
   - `JWT_SECRET` = любой секретный ключ для генерации токенов (например, `super_secret_key_123`).
5. Запустите СИД (seed) для создания первого администратора:
   ```bash
   npm run seed
   ```
6. Запустите сервер в режиме разработки:
   ```bash
   npm run dev
   ```
   Сервер запустится по адресу: `http://localhost:5000`

---

### Шаг 3: Запуск фронтенда (Client)

1. Откройте новый терминал и перейдите в каталог `client`:
   ```bash
   cd client
   ```
2. Установите зависимости:
   ```bash
   npm install
   ```
3. Создайте файл настроек:
   ```bash
   cp .env.example .env
   ```
   (Проверьте, что в `.env` параметр `VITE_API_URL` указывает на запущенный бэкенд: `http://localhost:5000`)
4. Запустите клиентское приложение:
   ```bash
   npm run dev
   ```
   Сайт откроется по адресу: `http://localhost:5173`

## ❓ Ответы на часто задаваемые вопросы

### 1. Как вернуть БД к исходному состоянию (сбросить)?
Если вам нужно полностью пересоздать базу данных, удалить зарегистрированных пользователей и сбросить бронирования, выполните в терминале:
```bash
# 1. Удаляем существующую базу и создаем её заново (выполнять из корня или в терминале PostgreSQL)
dropdb hotel_db && createdb hotel_db

# 2. Переходим в папку бэкенда и накатываем схему
cd server
npm run db:setup

# 3. Добавляем демонстрационного администратора
npm run seed
```
Это полностью сбросит структуру и наполнит комнаты демонстрационными значениями.

---

### 2. Как создается БД? Или она уже лежит в файлах?
* Особенность PostgreSQL заключается в том, что это **серверная СУБД**. Она не сохраняет данные внутри файлов вашего проекта (в отличие от SQLite). Данные физически хранятся внутри системной службы PostgreSQL на вашем ПК.
* При копировании папки проекта на другой компьютер, база данных не переносится автоматически. Вам необходимо на новом компьютере иметь установленный PostgreSQL, запустить его службу, создать чистую базу данных `hotel_db` и выполнить накатывание через `npm run db:setup` и `npm run seed`.

---

### 3. Почему при копировании проекта не сработали запускающие скрипты из корня?
Основной скрипт в корневом `package.json` настроен на использование флага `--prefix`. Например: `"dev": "npm run dev --prefix client"`.

Скрипты могут не сработать в другой папке по следующим причинам:
1. **Отсутствие установки зависимостей в корне**: Если вы перенесли проект, в корневой папке также нужно обязательно запустить `npm install` перед тем, как выполнять `npm run dev/server`. Сама команда npm внутри использует вспомогательные утилиты, кэшируемые в корневом `node_modules`.
2. **Разные версии Node.js / npm**: На некоторых версиях Windows/PowerShell или старых версиях npm флаг `--prefix` обрабатывается иначе или требует абсолютных путей. Оптимальным решением будет выполнять команды отдельно внутри папок `client` и `server`.
3. **Права доступа**: При копировании могли сброситься права на выполнение или доступ к поддиректориям.
